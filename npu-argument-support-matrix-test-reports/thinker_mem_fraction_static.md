# thinker_mem_fraction_static：NPU 参数验证报告

实机实验：2026-09-10；回归补充：2026-09-11。

## 参数用途与验证目标

Qwen3-Omni 的 Thinker 负责理解输入和生成文字。生成过程中，为避免重复计算而保存的中间信息称为“KV 缓存”。这个参数单独控制 Thinker 阶段的内存预算，不应误改语音生成阶段 Talker 的配置。

本次检查：NPU 是否需要独立的 Thinker 预算，设置是否传到正确计算进程、改变实际缓存，以及真实文字与语音请求是否能完成。

| 项目 | 说明 |
| --- | --- |
| NPU 是否需要 | 需要。Thinker 的模型和缓存需要在有限 NPU 内存中安排空间 |
| 当前入口 | `--thinker.engine.mem_fraction_static`；旧参数名称与当前 CLI 的差异是版本接口变化，不等于 NPU 不兼容 |
| 默认语义 | `None` 表示不手动指定，由模型和后端确定；不是分配零内存 |
| 实机范围 | Qwen3-Omni-30B-A3B-Instruct、Ascend910_9362、CANN 9.1.0；Thinker 分布在两张 NPU，Talker 等阶段用第三张卡；关闭图执行，最大运行请求数 2 |
| 结论 | 所测设置在两个 Thinker 进程生效并完成真实请求；无需新增参数适配代码 |

## 测试方法与结果

这个参数不只是要“改变一些内存”，还要作用在正确的阶段。因此，需要先看 Thinker 的计算进程是否收到设置，再看它实际分配的缓存是否随比例改变。本次 Thinker 的计算分布在两张 NPU 上，不能只检查其中一个进程，否则可能漏掉设置没有传到另一处的问题。

为了区分 Thinker 设置与 Talker 设置各自的作用，对照实验只改变 Thinker 比例，保持 Talker 配置不变，同时使用相同模型、请求和设备布局。如果把两个比例一起改动，就难以判断观察到的变化来自哪一个设置。这里固定的是另一阶段的配置，并不假定共享设备上的所有内存指标都会完全不变；实际差异仍需记录。

缓存分配正确后，还要确认整个服务能正常工作。所以每组都要求实际请求返回文字和完整音频，不能只停在引擎启动；另外取消手动设置，检查默认行为。这样分别回答“设置传到了哪里”“分配是否改变”和“改变后功能是否仍可用”。

具体对照中，Talker 保持 0.20，Thinker 分别设为 0.65 和 0.75。这些数用于本次比较，不是通用推荐值。每组先发送一次不计入正式耗时统计的请求进行预热，再发送 3 次相同设置的正式文字加语音请求。默认组将两个阶段的手动比例都恢复为 None。为避免其他设置控制缓存容量，本次不设 `max_total_tokens`（限制 token 容量）或 `kv_cache_bytes`（直接指定缓存字节数）。

| 检查项目 | Thinker 0.65 | Thinker 0.75 | 恢复默认路径 |
| --- | --- | --- | --- |
| 两个进程实际采用的比例 | 均为 0.65 | 均为 0.75 | 本次为 0.742，包含编码阶段预留调整 |
| 每个进程的 KV 容量 | 235,520 tokens | 369,152 tokens | 358,400 tokens |
| 每个进程 K、V 各自分配量 | 各 5.39 GB | 各 8.45 GB | 本表不作此项对照 |
| 每个进程就绪内存 | 40,711 MB | 46,995 MB | 本表不作此项对照 |
| 正式请求 | 3/3 成功，文字和音频完整 | 3/3 成功，文字和音频完整 | 3/3 成功 |
| 正式 HTTP 平均耗时 | 1.162 秒 | 1.115 秒 | 默认路径只判断功能通过 |

表中容量是每个计算进程的数据，不能把两份容量相加后解释为可接受的单条输入长度。两组显式比例均在对应进程观察到容量变化；短请求每组仅 3 次，不足以证明性能改善。

实机对照之外，还通过配置测试检查参数是否会被传错阶段；这类可重复运行的检查用于防止后续代码修改破坏现有行为。人为清空 Thinker 设置后，测试应当报出实际值与预期值不一致，即“断言失败”。音频内容则另作比较，不能由缓存容量正确直接推断内容正确。

| 补充检查 | 方法与结果 |
| --- | --- |
| 当前入口及阶段独立性 | CPU 配置测试从当前 CLI 路径解析，验证阶段设置覆盖全局设置且不误改另一阶段；检查非法值及阶段间缓存设置，均通过 |
| 测试是否能发现值丢失 | 在独立进程内清空 Thinker 比例，既有阶段测试产生 2 个断言失败，故障被检出 |
| 有无音频内容变化 | 包含本次对照在内的 Qwen 四组共 16 份音频哈希相同；每组抽一份识别，4 份均为“你好” |

## 结论边界

所测 Thinker 比例能改变实际 NPU 缓存，默认及显式设置均完成生成。默认 0.742 只对应本次模型与环境，不是所有机器的固定默认值。比例参与预算计算，不是进程总内存的硬上限。

Talker 配置虽固定为 0.20，在 Thinker 对照轮次中，其 KV 容量从 123,776 变为 113,152 tokens；当时 Talker 加载前可用内存也从 60.51 GB 变为 58.10 GB。同卡其他阶段初始化会影响容量，因此不能声称“另一阶段所有运行指标完全不变”。配置不串阶段与绝对内存容量不变是两回事。

没有 CUDA 实机对照；未验证所有模型、合法比例、图执行、长文本、极限并发或通用音质。“你好”的结果不能代替长文本质量评测。早期环境阻塞记录保留，不计入最终成功样本。
