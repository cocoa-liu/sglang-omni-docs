# talker_mem_fraction_static：NPU 参数验证报告

实机实验：2026-09-10；回归补充：2026-09-11。

## 参数用途与验证目标

Qwen3-Omni 的 Talker 负责生成语音表示，随后由后续阶段形成音频。它在生成过程中也需要保存中间计算信息，即“KV 缓存”。这个参数用于单独安排 Talker 的内存预算。

本次检查：NPU 是否需要该设置，调整 Talker 比例是否改变它自己的缓存，而不是误作用到 Thinker，以及服务能否继续生成完整音频。

| 项目 | 说明 |
| --- | --- |
| NPU 是否需要 | 需要。Talker 的模型和缓存同样需要有限设备内存 |
| 当前入口 | `--talker_ar.engine.mem_fraction_static`；报告保留兼容性表的参数名，测试使用当前有效入口 |
| 默认语义 | `None` 表示不手动指定，交给模型和后端决定，不是分配零内存 |
| 实机范围 | Qwen3-Omni-30B-A3B-Instruct、Ascend910_9362、CANN 9.1.0；Thinker 用两张 NPU，Talker 与其他设备阶段用第三张卡；关闭图执行，最大运行请求数 2 |
| 结论 | 所测 Talker 比例能独立改变其缓存分配，默认及显式设置完成生成；无需新增参数适配代码 |

## 测试方法与结果

这个参数负责 Talker 阶段的预算，因此验证不能只看整台设备的内存有没有变化。应当改变 Talker 比例，分别查看 Talker 和 Thinker 的记录：首先确认设置进入了 Talker，并改变它的缓存；再核对 Thinker，避免把作用到其他阶段的变化误认为本参数生效。

为分清变化的来源，对照实验保持 Thinker 配置不变，只修改 Talker，并使用相同模型、请求和设备布局。同时记录模型加载前后的可用内存，因为 Talker 与其他阶段共用一张卡：即使比例相同，其他阶段占用的空间不同，也可能使缓存容量不同。只有把这些条件一起核对，才能合理解释容量变化。

分配改变后，还需要实际生成音频。如果只看到缓存扩大，却不能完成语音请求，就不能说明这个设置在服务中可用。因此，每种设置下都发送相同请求，并另测取消手动设置的默认行为。

具体对照中，Thinker 保持 0.65，Talker 分别设为 0.20 和 0.30；这些数用于本次比较，不是通用推荐值。每组先发送一次不计入正式耗时统计的请求进行预热，再做 3 次正式文字加语音请求。默认组将两个阶段的手动比例都恢复为 None。为避免其他设置限制或替代缓存容量，本次不设 `max_total_tokens`（限制 token 容量）或 `kv_cache_bytes`（直接指定缓存字节数）。

| 检查项目 | Talker 0.20 | Talker 0.30 | 恢复默认路径 |
| --- | --- | --- | --- |
| Talker 实际比例 | 0.20 | 0.30 | 本次为 0.794 |
| Talker KV 容量 | 123,776 tokens | 256,000 tokens | 909,056 tokens |
| Talker 的 K、V 各自分配量 | 各 2.84 GB | 各 5.86 GB | 本表不作此项对照 |
| Talker 就绪进程内存 | 12,425 MB | 18,619 MB | 本表不作此项对照 |
| Thinker KV 容量，每个进程 | 235,520 tokens | 235,520 tokens | 两阶段均恢复默认，不用于隔离对照 |
| 正式请求 | 3/3 成功，文字和音频完整 | 3/3 成功，文字和音频完整 | 3/3 成功 |
| 正式 HTTP 平均耗时 | 1.162 秒 | 1.146 秒 | 默认路径只判断功能通过 |

两组显式比例的 Talker 加载前可用内存均为 60.51 GB、加载后均为 54.18 GB。改变比例后，Talker 缓存扩大，而 Thinker 缓存保持一致，支持“设置作用于正确阶段”的判断。

实机结果之外，还通过可重复运行的配置测试检查参数传递和阶段独立性。人为清空 Talker 设置后，测试应因实际值不符合预期而报错，即“断言失败”，以确认它能发现这种退化。最后比较输出音频，检查本组请求中是否出现内容变化。

| 补充检查 | 方法与结果 |
| --- | --- |
| 当前入口及阶段独立性 | CPU 配置测试检查路径解析、阶段覆盖、非法值及阶段间缓存配置；对应检查通过 |
| 测试是否能发现参数丢失 | 在独立进程内清空 Talker 比例，既有阶段测试产生 2 个断言失败，故障被检出 |
| 音频内容是否变化 | Qwen 四组共 16 份音频哈希相同；每组抽一份用 Whisper small 识别，4 份均为“你好” |
| 相同比例是否必然产生相同容量 | 另一轮同为 0.20 时容量为 113,152 tokens，加载前可用内存为 58.10 GB；说明容量还受同卡其他阶段的加载影响 |

## 结论边界

现有实现支持所测 Talker 内存设置，并完成真实生成。0.794 是本轮默认结果，不是所有模型或环境的固定默认值。比例参与内存预算，不承诺相同比例在不同可用内存下产生相同绝对容量。

每组短请求仅 3 次，耗时不构成性能提升证明；16 份“你好”音频也不构成长文本或通用音质验证。没有 CUDA 实机对照，未覆盖全部模型、比例、图执行或极限并发。早期环境阻塞记录保留，不计入最终成功样本。
