# mem_fraction_static：NPU 参数验证报告

实机实验：2026-09-10；回归补充：2026-09-11。

## 参数用途与验证目标

模型运行时，设备内存既要放模型，也要保存生成中已经计算过的信息。这部分中间信息称为“KV 缓存”，用于避免后续生成反复计算。

`mem_fraction_static` 是通用内存比例设置，会传给模型引擎阶段并参与缓存预算计算。本次检查：NPU 是否需要它，改变比例是否真的改变缓存分配，以及服务是否仍能完成正常生成。

| 项目 | 说明 |
| --- | --- |
| NPU 是否需要 | 需要。NPU 内存同样有限，需要给模型、缓存和运行开销分配空间 |
| 当前入口 | `--mem-fraction-static`；更具体的阶段设置优先于通用设置 |
| 默认语义 | 不手动指定时由模型与后端决定，不是把内存设为零 |
| 实机范围 | Fun-CosyVoice3-0.5B-2512、Ascend910_9362、CANN 9.1.0 归档环境；关闭图执行，最大运行请求数 2 |
| 结论 | 所测默认值与显式设置均生效并完成真实生成；无需新增 NPU 专用参数代码 |

它不是“进程总内存必须等于设备容量乘比例”的硬上限。实际缓存还受可用内存、模型占用和其他预留空间影响；缓存 token 数是容量单位，不能直接换算成并发用户数。

## 测试方法与结果

这个参数要改变的是内存分配。因此，服务能够启动、命令里能够填写比例，还不能证明它被真正使用。应当在其他条件尽量相同的情况下改变比例，再查看实际分配的缓存容量：如果设置的变化确实传到了内存分配环节，就应当在容量记录中看到相应变化。同时记录设备进程占用的内存，用来辅助核对实际分配，而不是只抄下启动命令中的数值。

比较时需要固定模型、NPU 和请求内容，因为换模型或改变其他内存设置，也可能使缓存容量变化。另有两个设置会干扰这个判断：`max_total_tokens` 可以限制缓存的 token 容量，`kv_cache_bytes` 可以直接指定缓存字节数。如果同时使用它们，观察到的容量可能受另一个限制控制。因此本次不设置这两项，尽量单独观察内存比例的作用。

容量变化还不等于服务可用：内存重新分配后，模型仍应完成正常生成。因此每个比例下还要提交相同的语音任务，检查返回的音频；并测试不手动设置的情况，确认默认行为也能使用。

按照这个思路，本次选择 0.15 和 0.25 两个不同的比例进行对照，另测不手动设置；这两个数是实验取值，不是推荐配置。每组先完成一次单条生成，再分别发送一次包含 1 条任务和一次包含 2 条任务的批量请求进行预热，让首次执行所需的初始化先完成。之后，对这两种请求各正式重复 3 次，即每组共 6 次批量请求、9 条生成任务。重复请求用于记录这一固定负载下的表现，不是极限并发测试。

| 检查项目 | 0.15 | 0.25 | 不手动设置 |
| --- | --- | --- | --- |
| 实际 KV 容量 | 711,936 tokens | 1,246,080 tokens | 4,451,072 tokens；本模型实际默认比例 0.85 |
| K、V 各自分配量（日志单位） | 各 4.07 GB | 各 7.13 GB | 各 25.47 GB |
| 服务就绪进程内存 | 11,067 MB | 17,359 MB | 本表不作此项对照 |
| 单条请求 | 成功、音频完整 | 成功、音频完整 | 成功、音频完整 |
| 正式批次，不含预热 | 6 批、9 条全部成功 | 6 批、9 条全部成功 | 6 批、9 条全部成功 |

0.15 与 0.25 两组模型加载前可用内存均为 61.12 GB，加载后均为 60.11 GB。比例增加 0.10 后，KV 增加 534,144 tokens，同时观察到进程内存增加；这才是参数影响实际分配的证据。

除缓存容量外，还记录请求耗时、内存采样和音频内容，观察调整后是否出现明显问题。另用不运行模型的配置测试检查参数传递和非法值；这类可重复执行的检查称为回归测试。最后人为让参数不再传递，确认测试会因实际值不符合预期而报错，即下表的“断言失败”。

| 补充检查 | 结果 | 如何理解 |
| --- | --- | --- |
| 1 条批次 HTTP 平均耗时 | 0.15：1.834 秒；0.25：1.905 秒 | 每组仅 3 次，包含排队、预处理与生成，不证明性能提升或退化 |
| 2 条批次 HTTP 平均耗时 | 0.15：1.852 秒；0.25：1.951 秒 | 同上，不是极限吞吐测试 |
| 进程内存采样最大值 | 12,155 / 18,447 MB | 包含批次预热，每组仅 8 次采样，可能遗漏瞬时峰值 |
| 音频转写复核 | 两个显式比例各测 12 份；统一数字表达后均为 8/12 一致，4 份有“语音/译音”差异 | 两组现象相同，不能归因于内存比例，也不宣称发音全部正确 |
| 配置回归 | 全局分发、默认值、非法值、覆盖优先级和缓存配置冲突检查通过 | 属于 CPU 配置测试，不是 NPU 推理 |
| 参数丢失故障检出 | 返回正确类型的空配置补丁，模拟全局设置未传播 | 9 个值比较断言失败，故障被检出 |

## 结论边界

现有实现能控制所测 NPU 配置的缓存容量，合法请求完成生成。没有验证全部模型、全部合法比例、图执行、长上下文或极限并发，也没有 CUDA 实机对照。缓存扩大不保证短请求更快。

初期 CANN 9.0 环境曾出现 Ascend 507015；切换到 CANN 9.1 软件组合后完成测试。两组环境存在多项依赖差异，不能把某一版本断定为唯一根因，也不能把旧环境失败写成“参数不需要支持”。
