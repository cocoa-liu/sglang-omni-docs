# allowed_media_domain：NPU 参数验证报告

实机实验：2026-09-07；回归补充：2026-09-11。

## 参数用途与验证目标

SGLang-Omni 可以接收一段示例声音，再生成新的语音。这段示例声音称为“参考音频”。通过网址提供参考音频时，服务需要先下载它；`allowed_media_domain` 设置允许下载的域名名单，而不是某个音频文件的完整网址。

本次要确认：服务换用 NPU 后，是否仍需要这个限制；现有实现是否能拒绝禁止来源，并让合法来源继续完成真实生成。

| 项目 | 说明 |
| --- | --- |
| NPU 是否需要 | 需要。只要保留网址参考音频输入，就仍需控制下载来源 |
| 实现方式 | 共用服务代码检查来源，合法输入随后进入模型；不需要为每个模型重写域名校验 |
| 实机范围 | Fun-CosyVoice3-0.5B-2512、Ascend910、本次归档配置；引擎最多同时运行 2 条请求 |
| 结论 | 所测配置下，限制生效且合法请求完成生成；无需新增 NPU 专用参数逻辑 |

## 测试方法与结果

这个参数的作用是区分“可以下载的来源”和“不可以下载的来源”。因此，只测一个网址成功或失败都不够：成功可能是服务根本没有检查名单，失败也可能只是网址无法访问。需要在同一份允许名单下，分别检查允许来源能通过、禁止来源因名单限制而被拒绝，才能判断这条规则是否生效。

还要区分“下载成功”和“功能可用”。下载下来的参考音频只是模型的输入，用户最终需要的是模型生成的新音频。因此，允许来源的测试必须继续走到真实 NPU 生成；禁止来源则应在下载前被拦截。为确认后一点，另外用可控的网络响应记录下载代码访问了哪些地址，而不是仅凭最终报错猜测。网址可能跳转到另一个网站，所以也要检查跳转后的目标仍受限制。

本次先设置允许名单，提交名单内和名单外的参考音频网址，再检查拒绝后合法请求是否仍能完成。不设置名单的情况单独测试，用于确认默认行为。下表分别列出真实生成与共用代码检查的结果；其中“回归测试”是以后修改代码时可重复运行的检查，“断言失败”表示实际结果与测试预期不一致。

| 要确认什么 | 具体怎么测 | 通过标准 | 实际结果 |
| --- | --- | --- | --- |
| 允许来源可用 | 在真实 NPU 服务中允许 `raw.githubusercontent.com`，提交该域名的固定参考音频 | 下载后继续生成，返回完整输出音频 | 通过 |
| 禁止来源被拦截 | 保持允许名单，提交名单外的网址 | 明确因域名不被允许而拒绝 | 通过 |
| 拒绝不破坏服务 | 拒绝后再发送合法请求 | 仍可生成完整音频 | 通过 |
| 默认行为可用 | 不设置名单，提交公开参考音频网址 | 公开来源能用于生成 | 通过；指向服务器自身的地址仍被另一项安全规则拒绝 |
| 限制发生在下载前 | 用可控网络响应记录访问目标，并测试重定向到禁止域名 | 不访问禁止目标，跳转不能绕过限制 | 共用代码测试通过；不是额外的 NPU 推理 |
| 域名写法正确处理 | 测试大小写、末尾点、子域名与相似但不应允许的名称 | 按既定规则允许或拒绝 | 共用代码测试通过 |
| 批量单项不能绕过限制 | 批次默认使用允许来源，其中一项改为禁止来源 | 合法项进入处理，非法项报错且不下载 | 2026-09-11 轻量接口测试通过；合法音频字节也保持一致 |
| 回归测试能发现参数丢失 | 在独立进程内人为丢失域名列表，再运行已有配置测试 | 测试因接收到的名单不符合预期而失败 | 1 个断言失败，故障被检出；未改磁盘上的产品源码 |

## 结论边界

| 可以确认 | 不能据此确认 |
| --- | --- |
| 所测 NPU 服务上，域名限制与合法生成共同成立 | 所有模型、所有网址或所有网络安全情形均已验证 |
| 不设名单时仍有正常默认行为 | 不设名单等于取消全部安全限制 |
| 参考音频下载成功，模型也返回完整的新音频 | 输出声音与参考声音足够相似，或声音克隆质量已通过 |

没有 CUDA 实机对照。本次整理不新增实验，也不修改上游兼容性表的勾选。
